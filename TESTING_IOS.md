# Как тестировать Salvio для iOS

Ступени: сейчас без Mac (CI, Appetize в браузере, Sideloadly на iPhone), с Mac на время (симулятор и свой iPhone на 7 дней),
после покупки Apple Developer ($99 в год, TestFlight). Команды даны по одной,
перед каждой написано, где её выполнять и что должно появиться.

---

## 0. Что уже проверяется без Mac: GitHub Actions

Каждый push в репозиторий `Andrey7sh/app_salvio_ios` запускает на macOS-раннере:
генерацию проекта XcodeGen, сборку под симулятор без подписи и unit-тесты
(парсинг ответов API, план загрузки чанков, восстановление после убийства приложения,
формат аудио ADTS, валидация форм). Это проверка компиляции, но не проверка интерфейса и записи с микрофона.

**Посмотреть последние прогоны.** Локально, Windows, PowerShell:

```powershell
gh run list -R Andrey7sh/app_salvio_ios -L 5
```

В ответ: таблица, в первой колонке `completed`, во второй `success` или `failure`.

**Открыть прогон в браузере** (подставь номер из последней колонки таблицы вместо 123):

```powershell
gh run view 123 -R Andrey7sh/app_salvio_ios --web
```

**Перезапустить проверку без нового коммита.** Локально, PowerShell:

```powershell
gh workflow run ios.yml -R Andrey7sh/app_salvio_ios --ref feat/ios-app
```

В ответ: `Created workflow_dispatch event for ios.yml`. Через 2-3 минуты прогон появится в `gh run list`.

Репозиторий с 21.09.2026 публичный: на публичных репозиториях минуты Actions бесплатны и без лимита.
В приватном режиме минута macOS списывалась как 10 минут квоты, и месячные 2000 минут закончились
после полутора десятков прогонов. Если снова сделать репозиторий приватным, следи за балансом
на github.com/settings/billing: при исчерпании прогоны падают за несколько секунд без логов.

## 0.1. Посмотреть приложение без Mac: Appetize в браузере

Каждый прогон CI собирает приложение под симулятор и выкладывает архив `Salvio-simulator.zip`
(хранится 14 дней). Appetize запускает его на настоящем симуляторе iPhone прямо в браузере на Windows.
Работает вход на прод, список, детали, «Поделиться». Не работает: запись с микрофона, звонок посреди записи, фон.

**Скачать архив последнего прогона.** Локально, Windows, PowerShell. Сначала перейди в папку загрузок:

```powershell
cd $HOME\Downloads
```

```powershell
gh run download -R Andrey7sh/app_salvio_ios -n Salvio-simulator
```

В ответ ничего не печатается, в папке «Загрузки» появляется `Salvio-simulator.zip`.
Если ответ `no valid artifacts found`, значит последний прогон ещё идёт или упал: проверь `gh run list` из раздела 0.

**Загрузить в Appetize.**
1. Зайди на appetize.io, зарегистрируйся (есть бесплатный лимит минут в месяц).
2. Upload → выбери `Salvio-simulator.zip` → Platform: iOS.
3. Открой ссылку на приложение, выбери iPhone и нажми Tap to play.

Для новой версии загружай новый архив в то же приложение в Appetize (кнопка обновления сборки), ссылка останется прежней.

## 1. Mac на время: облачная аренда или свой

Нужен Mac с macOS 14.5 или новее и Xcode 16 или новее.

Варианты аренды:
- **MacinCloud** (macincloud.com): почасовой тариф Pay-As-You-Go, вход через браузер или RDP, Xcode уже стоит.
- **AWS EC2 Mac** и **Scaleway Apple silicon**: минимальный срок аренды 24 часа, дороже для разовой проверки.

Оплата российской картой у этих сервисов обычно не проходит, понадобится зарубежная карта.
Облачный Mac подходит для симулятора. Свой iPhone к нему по кабелю не подключить,
для установки на телефон (раздел 2) нужен физический Mac рядом с тобой.

### 1.1. Подготовка (один раз)

Все команды ниже выполняются **на Mac в приложении Терминал** (Finder → Программы → Утилиты → Терминал).

Проверить Xcode:

```bash
xcodebuild -version
```

В ответ: `Xcode 16.x` и `Build version ...`. Если `command not found`, установи Xcode из App Store и открой его один раз, чтобы он доустановил компоненты.

Проверить Homebrew:

```bash
brew --version
```

Если `command not found`, установи его (одна длинная строка, скопируй целиком):

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

В конце установщик напишет `Next steps` с двумя командами `echo ... >> ~/.zprofile` и `eval ...`, выполни их как есть.

Установить XcodeGen и GitHub CLI:

```bash
brew install xcodegen gh
```

В ответ в конце: `xcodegen ... was successfully installed` (или `Pouring ...` без ошибок).

Войти в GitHub (репозиторий приватный):

```bash
gh auth login
```

Отвечай стрелками и Enter: `GitHub.com` → `HTTPS` → `Yes` → `Login with a web browser`. Скопируй код из терминала, вставь в открывшемся браузере.
В ответ: `✓ Logged in as Andrey7sh`.

Скачать проект:

```bash
gh repo clone Andrey7sh/app_salvio_ios
```

```bash
cd app_salvio_ios
```

```bash
git checkout feat/ios-app
```

В ответ: `Switched to a new branch 'feat/ios-app'`.

### 1.2. Каждый раз после обновления кода

```bash
git pull
```

```bash
xcodegen generate
```

В ответ: `Created project at .../Salvio.xcodeproj`. Файл `.xcodeproj` в git не хранится, его всегда создаёт эта команда.

### 1.3. Запуск в симуляторе

```bash
open Salvio.xcodeproj
```

В Xcode: вверху по центру выбери схему `Salvio` и устройство `iPhone 16` (любой iPhone из списка), нажми **Cmd+R**.
Откроется симулятор с экраном «Вход».

Что можно проверить в симуляторе:
- регистрация, вход, выход, ошибки формы;
- профиль работы и баланс на экране «Запись» (сценарий меняется в веб-кабинете, после смены потяни вниз экран «Профиль»);
- список встреч, детали, секции сценария, чек-лист, транскрипт, «Поделиться» (ссылка открывается в Safari симулятора);
- запись: симулятор пишет с микрофона Mac. На облачном Mac микрофона нет, запишется тишина, но цепочка «чанки → загрузка → обработка» проверяется;
- фон: во время записи **Cmd+Shift+H** (домой), подожди минуту, вернись, таймер должен идти;
- убийство приложения: во время записи нажми в Xcode **Cmd+.** (Stop), затем снова **Cmd+R**. Во вкладке «Встречи» запись появится в разделе «На телефоне» и уйдёт на сервер.

Входящий звонок и Siri в симуляторе не воспроизвести, это проверяется только на iPhone.

Прогнать unit-тесты из терминала (то же, что делает CI). Сначала узнай имя симулятора:

```bash
xcrun simctl list devices available
```

В ответ: список вида `iPhone 16 (XXXXXXXX-...) (Shutdown)`. Подставь имя в команду:

```bash
xcodebuild test -project Salvio.xcodeproj -scheme Salvio -destination "platform=iOS Simulator,name=iPhone 16" CODE_SIGNING_ALLOWED=NO
```

В конце: `** TEST SUCCEEDED **`.

## 2. Свой iPhone без Mac: Sideloadly на Windows (7 дней, бесплатно)

CI собирает неподписанный `Salvio.ipa`. Sideloadly подписывает его твоим Apple ID и ставит на iPhone по кабелю.
Приложение работает 7 дней, потом ставится заново так же. Запись, фон и звонки проверяются полностью.

Sideloadly сторонняя программа и просит пароль Apple ID. Лучше завести отдельный Apple ID для тестов.

**Один раз:**
1. Установи iTunes с сайта Apple: apple.com/itunes → «Windows» → скачать версию для Windows (не из Microsoft Store).
2. Установи Sideloadly с sideloadly.io.
3. Подключи iPhone кабелем, на телефоне нажми «Доверять этому компьютеру» и введи код телефона.

**Скачать сборку.** Локально, Windows, PowerShell:

```powershell
cd $HOME\Downloads
```

```powershell
gh run download -R Andrey7sh/app_salvio_ios -n Salvio-iphone
```

В ответ ничего не печатается, в «Загрузках» появляется `Salvio.ipa`.

**Установить:**
1. Открой Sideloadly. Вверху в поле iDevice должен быть виден твой iPhone.
2. Перетащи `Salvio.ipa` в окно Sideloadly (на иконку IPA слева).
3. В поле Apple account введи Apple ID, нажми **Start**, введи пароль (и код двухфакторной защиты, если спросит).
4. Внизу должно появиться `Done.`
5. На iPhone: **Настройки → Основные → VPN и управление устройством** → твой Apple ID → **Доверять**.
6. На iPhone: **Настройки → Конфиденциальность и безопасность → Режим разработчика → включить**, перезагрузить, подтвердить.
   Пункт появляется только после установки приложения из шага 3.
7. Открой Salvio, войди, разреши микрофон.

Если Sideloadly пишет, что Bundle ID занят: Advanced options → **Change bundle ID** → например `io.salvio.app.test`.

### Обновление уже установленного приложения

Удалять старое приложение не нужно: Sideloadly ставит новую сборку поверх, если совпадает Bundle ID.
Вход в аккаунт, согласие и неотправленные записи сохраняются, семидневный срок подписи отсчитывается заново.

1. Скачай свежую сборку: `gh run download -R Andrey7sh/app_salvio_ios -n Salvio-iphone` (сначала `cd $HOME\Downloads`).
   Если файл с таким именем уже лежит, старый удали, иначе команда ругнётся.
2. Подключи iPhone кабелем, открой Sideloadly, перетащи `Salvio.ipa`, введи тот же Apple ID и нажми **Start**.
3. Если при первой установке ты менял Bundle ID в Advanced options, поставь ровно тот же. Другой Bundle ID
   поставит вторую копию приложения рядом, со своими записями и своим входом.
4. После `Done.` открой приложение. Повторно доверять разработчику в настройках обычно не нужно.

Если Sideloadly ругается на лимит App ID (у бесплатного Apple ID их 10 на 7 дней), включи в Advanced options
**Remove app extensions**: приложение поставится без виджета, то есть без плашки «Идёт запись» на экране блокировки.
Остальное, включая запись в фоне, работает как обычно.

## 2.1. Свой iPhone бесплатно на 7 дней через Xcode (нужен физический Mac)

Бесплатный Apple ID даёт «Personal Team»: приложение живёт на телефоне 7 дней, потом его нужно
установить заново из Xcode. Одновременно не больше 3 таких приложений. Фоновая запись и фоновая загрузка работают.

1. На iPhone (iOS 16 или новее): **Настройки → Конфиденциальность и безопасность → Режим разработчика → включить**, телефон перезагрузится, подтверди включение.
2. Подключи iPhone кабелем к Mac, на телефоне нажми «Доверять этому компьютеру».
3. В Xcode: **Xcode → Settings → Accounts → «+» → Apple ID**, войди своим Apple ID.
4. В Xcode слева нажми на проект `Salvio` → таргет `Salvio` → вкладка **Signing & Capabilities**:
   - Team: `Твоё имя (Personal Team)`;
   - Bundle Identifier: замени `io.salvio.app` на уникальный, например `io.salvio.app.andrey`.
     Эти правки живут в `.xcodeproj` и пропадут после `xcodegen generate`, повтори их после генерации.
5. Вверху выбери свой iPhone вместо симулятора, нажми **Cmd+R**.
6. Первый запуск упадёт с «Untrusted Developer». На iPhone: **Настройки → Основные → VPN и управление устройством → Apple Development: твой e-mail → Доверять**. Снова **Cmd+R** в Xcode.

### Обновление на Mac поверх версии, поставленной Sideloadly

Приложение ставится поверх и сохраняет вход, согласие и неотправленные записи, если совпадают
две вещи: **Bundle ID** и **Apple ID**, которым подписана старая установка. Тогда для iOS это та же
программа, просто новее.

В папке проекта на Mac, в Терминале:

```bash
git pull
```

```bash
xcodegen generate
```

```bash
open Salvio.xcodeproj
```

Дальше в Xcode: **Signing & Capabilities** → Team твой Personal Team, Bundle Identifier ровно тот же,
что вводил в Sideloadly. Подключи iPhone, выбери его вверху и нажми **Cmd+R**. Приложение обновится,
семь дней подписи отсчитываются заново.

Если Xcode скажет, что установить нельзя (`application identifier не совпадает` или подпись другой
команды), значит старая сборка подписана другим Apple ID. Тогда старое приложение придётся удалить с
телефона: загруженные встречи останутся на сервере, а неотправленные куски записей пропадут, поэтому
сначала открой приложение и дождись, чтобы раздел «На телефоне» опустел.

Бесплатный Apple ID разрешает 10 идентификаторов приложений за 7 дней, а у нас их два: само приложение
и виджет с индикатором записи. Если лимит исчерпан, Xcode об этом скажет прямо, тогда подожди или
временно убери таргет `SalvioWidgets` из схемы.

### Что проверить на iPhone (главное, чего не покажет симулятор)

- Запись 12+ минут с заблокированным экраном: должно получиться 3 чанка по 5 минут, запись целиком на сервере.
- Входящий звонок во время записи: после звонка запись продолжается сама, иначе на экране кнопка «Продолжить».
- Siri и будильник во время записи: то же самое.
- Авиарежим во время записи: запись идёт, после выключения авиарежима чанки уходят (вкладка «Встречи», раздел «На телефоне»).
- Смахнуть приложение из переключателя во время записи, открыть снова: записанное до этого момента уходит на сервер.
- Аккаунт без минут: встреча получает статус «Ждёт оплаты», в деталях «Недостаточно минут на балансе», ни ссылок, ни призывов пополнить.
- «Поделиться»: ссылка открывается в Safari без входа.
- В веб-кабинете app.salvio.io встреча с iPhone проигрывается целиком, без обрывов на стыках чанков.

Сам аудиоформат уже проверен: unit-тест в CI пишет чанк с настройками диктофона и читает его обрезанным,
а серверная склейка ffmpeg на таких файлах проверена локально. Остаётся убедиться на живой записи.

## 3. TestFlight после покупки Apple Developer Program ($99 в год)

1. Регистрация: developer.apple.com/programs → Enroll. Как физлицо быстрее; как ИП или ООО нужен D-U-N-S номер.
   Российские карты Apple к оплате не принимает, нужна зарубежная карта.
2. После подтверждения (от суток до нескольких дней) в **App Store Connect** (appstoreconnect.apple.com):
   **Apps → «+» → New App**, платформа iOS, Bundle ID `io.salvio.app`, SKU любой, например `salvio-ios`.
3. На Mac в Xcode: **Signing & Capabilities → Team** = команда разработчика (не Personal Team), Bundle Identifier вернуть на `io.salvio.app`.
4. Вверху выбрать устройство **Any iOS Device (arm64)**, затем **Product → Archive**.
5. В открывшемся Organizer: **Distribute App → App Store Connect → Upload**, дальше «Next» с настройками по умолчанию.
6. Через 10-30 минут сборка появится в App Store Connect → твоё приложение → **TestFlight**.
   Ответь на вопрос про шифрование (в проекте уже стоит `ITSAppUsesNonExemptEncryption = NO`, вопрос может не появиться).
7. **TestFlight → Internal Testing → «+»**, добавь e-mail тестировщиков (они должны быть пользователями App Store Connect).
8. На iPhone установи приложение **TestFlight** из App Store, прими приглашение из письма, установи Salvio. Сборка живёт 90 дней.

Номер сборки для каждой новой загрузки нужно увеличивать: в `project.yml` поле `CURRENT_PROJECT_VERSION`.

Позже загрузку в TestFlight можно перенести в GitHub Actions (без Mac): понадобятся ключ App Store Connect API
и сертификат подписи. Их кладём только в GitHub Secrets, в репозиторий никогда.

## 4. Что закрыть до отправки в App Store на ревью

- **Удаление аккаунта из приложения** (правило App Store 5.1.1(v)). Сделано: кнопка «Профиль → Удалить аккаунт»
  и `DELETE /api/auth/me` в salvio-web (ветка `feat/account-delete`). Осталось смержить и выкатить на прод,
  до этого кнопка возвращает ошибку.
- **Правило 3.1.3(f)**: приложение бесплатное и служит компаньоном к платному веб-сервису. В нём нет цен, покупок,
  ссылок на оплату и призывов пополнить баланс где-то ещё: только состояние («Недостаточно минут на балансе»).
  В заметках для ревьюера так и написать: free companion app to a paid web service, guideline 3.1.3(f).
  Новые тексты про минуты проверять на это правило.
- **Демо-аккаунт для ревьюера**: `demo@salvio.io`, 300 минут на балансе, почта подтверждена, профиль работы задан.
  Пароль лежит в менеджере паролей Андрея, в репозитории его нет. Перед отправкой на ревью запиши этой учёткой
  одну короткую встречу, чтобы ревьюер увидел готовый результат.
- **App Privacy** в App Store Connect: собираются e-mail, имя, аудиозаписи и транскрипты, всё для работы приложения,
  без трекинга (то же самое продублировано в `Salvio/PrivacyInfo.xcprivacy`).
- **Раскрытие подрядчиков обработки** (5.1.2(i)): на экране согласия перед первой записью они пока описаны обобщённо,
  Apple требует называть их. Решение за Андреем.
- **Новая редакция `salvio.io/mob_terms`**: действующая говорит, что доступ выдаёт работодатель, про саморегистрацию,
  удаление аккаунта и передачу данных подрядчикам там ничего нет.
- **Support URL**: нужна обычная веб-страница, Telegram-бот App Store Connect не примет.
- Скриншоты 6.9" и 6.5" iPhone, описание, ссылка на политику конфиденциальности (`https://salvio.io/mob_terms`).
